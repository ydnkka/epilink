# Boston source-data processing: 4 March–9 May 2020

Sequences and metadata from [Lemieux et al. (2021)](https://www.science.org/doi/10.1126/science.abe3261) were downloaded from the project's [Terra Workspace](https://app.terra.bio/#workspaces/pathogen-genomic-surveillance/COVID-19_Broad_Viral_NGS).

These notes describe the source alignment, annotations, and distance table used
by the [Boston application](../../../evaluation/03_boston_application/README.md).
Run all commands below from the **repository root**. Normal evaluation consumes
the supplied source files; Nextclade and the first TN93 command below are input
generation steps rather than requirements to repeat before each evaluation.

## Sequence analysis with [`Nextclade`](https://docs.nextstrain.org/projects/nextclade/en/stable/index.html)

To assign clades, Nextclade places query sequences on a reference tree
representative of the global phylogeny and annotates mutations relative to the
reference sequence. Dataset versions affect these annotations; the supplied
dataset metadata and changelog are under `data/sars-cov-2/`.

[Nextclade Result Table Columns Meaning](https://docs.nextstrain.org/projects/nextclade/en/stable/user/output-files/04-results-tsv.html)

STEP 1

```bash
nextclade dataset get --name "nextstrain/sars-cov-2/wuhan-hu-1/orfs" --output-dir "data/sars-cov-2"
```

STEP 2

```bash
nextclade run \
    --input-dataset "data/sars-cov-2" \
    --output-fasta "data/raw/boston/MGH_DPH_98percent_772samples_aligned.fasta" \
    --output-tsv "data/raw/boston/MGH_DPH_98percent_772samples_nextclade.tsv" \
    --include-reference false \
    "data/raw/boston/MGH_DPH_98percent_772samples.fasta"
```

## Genetic-distance input table

The aligned sequences generated by Nextclade were used to calculate pairwise genetic distances with the standalone package [tn93](https://github.com/veg/tn93), which implements the [TN93 substitution model](https://academic.oup.com/mbe/article/10/3/512/1016366). Ambiguous nucleotides were handled using the `resolve` strategy (`-a resolve`), whereby ambiguous nucleotides were resolved to minimise the pairwise genetic distance where possible. The maximum tolerated fraction of sites containing resolvable ambiguities was set to 0.05 (`-g 0.05`); pairwise comparisons exceeding this fraction were instead averaged. Only pairwise comparisons with at least 500 nucleotides of overlapping sequence were processed (`-l 500`). The reporting cutoff was 0.0005 substitutions per site (`-t 0.0005`). Progress and diagnostic messages were suppressed using `-q`.

The input adapter scales TN93 distance by the reference length of 29,903
nucleotides to obtain `GD`. This can be fractional and is not an integer SNP or
Hamming-distance count.

The corresponding source-distance command is:

```bash
tn93 -q -t 0.0005 -a resolve -g 0.05 -l 500 -o "data/raw/boston/MGH_DPH_98percent_772samples_tn93_distances.csv" "data/raw/boston/MGH_DPH_98percent_772samples_aligned.fasta"
```

## Evaluation input preparation and tree construction

```bash
python evaluation/03_boston_application/run.py --stage prepare
```

The adapter joins metadata and Nextclade annotations, removes self-pairs,
canonicalizes unordered pair IDs, and computes **absolute** sample-date
differences in days as `TD`. It writes `cases.parquet`, `observed_pairs.parquet`,
and a provenance manifest under `evaluation/03_boston_application/outputs/inputs/`.
Missing pairs from the censored TN93 table remain unobserved, not zero-distance.
The [output reference](../../../OUTPUTS.md#10-boston-inputs-and-results) defines
the columns and exposure-label assignment.

Boston tree construction separately runs TN93 with `-t 1` on the alignment and
requires every distinct case pair to have a finite distance. It builds raw trees
with FastME and dated trees with TreeTime using collection dates. These all-pair
distances are stored with tree artifacts; they do not replace the censored table
used by the graph-scoring workflow. EpiLink produces compatibility scores, while
the baseline-fitted logistic models produce probabilities.
